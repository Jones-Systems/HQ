HQ preview installation and recovery

Packages are architecture-specific: arm64 for Apple silicon, x64 for Intel.
Use a published hq-desktop-* tag from Jones-Systems/HQ. Pull-request artifacts
are build evidence, not authenticated update releases.

Before running any downloaded program, independently verify BOTH the archive
and manifest against the release's .sigstore.json bundle. The verifier must
check the signature, Fulcio certificate and transparency evidence, exact
Jones-Systems/HQ repository and exact source commit, the workflow
.github/workflows/hq-desktop-package.yml, run ID/attempt, and both SHA-256
subjects. For example, a separately trusted GitHub CLI supports
`gh attestation verify <asset> --repo Jones-Systems/HQ --bundle <bundle>`;
inspect its verified source/workflow/ref details against the exact selected
release. A successful workflow run or a hash copied from an unverified
manifest does not authenticate bytes. Keep the independently verified archive
SHA-256. The launcher extracts that exact archive into its own new directory;
it never executes an app supplied separately from the authenticated archive.

Development previews have an ad-hoc signature with strict deep code-seal
verification. They make no Developer ID or notarization claim. Production
releases use hq-desktop-signed-<runId> and require a manifest with
signing=developer-id, sourceRef=refs/heads/main and Team 2CUPSQS986. Their
attestation must name a push from the fixed main branch in the same repository
and workflow, with the exact source commit/run/attempt and BOTH asset digests.
Independently resolve the release tag to that same commit. A tag reference in a
production attestation, another branch, or a manifest-selected workflow is not
an accepted substitute. Production native admission checks identifier
org.jones-systems.hq.local, hardened runtime, secure timestamp, the Developer ID
certificate requirement, stapled notarization and Gatekeeper assessment.

Gatekeeper or Keychain prompts still require normal macOS owner interaction.
This installer does not grant consent or promise measured permission continuity.
A prompt that cannot be handled interactively is a hold, not successful
installation. Never remove quarantine or change signing/account settings as
an automated workaround. Production updates reject ad-hoc downgrade candidates;
exact retained rollback bundles remain subject to their recorded signing policy
and the existing profile compatibility gates.

Fresh installation uses the authenticated bundle's Electron runtime, so no
system Node or Python is required. From the release files, run:

  bash install-hq.command /absolute/hq-darwin-arm64.zip <verified-sha256>

For Intel, select hq-darwin-x64.zip. The optional third argument is an absent
absolute per-user .app target. The default is $HOME/Applications/HQ.app.
Existing targets are refused. A fresh installation creates an explicit,
installation-owned profile; it does not discover or adopt an existing profile.
The launcher's own extracted runtime is removed when its installer process
exits; the updater's verified candidate cache has its own retained lifetime.
Keep the externally stored installation record and update-state directory.
Do not run a second installer while an installation result is unknown.

Existing-installation adoption requires exact operator-supplied source-only
legacy hashes, target, state root and preserved userData/sessionData pins. It
uses `installer.cjs adopt --input <operator-metadata.json>` from the verified
runtime. It is not inferred from an existing target or from profile contents.

To inspect an installation, use an independently authenticated retained bundle:

  ELECTRON_RUN_AS_NODE=1 /absolute/verified/HQ.app/Contents/MacOS/HQ /absolute/verified/HQ.app/Contents/Resources/app/tools/updater/installer.cjs inspect --target /absolute/installed/HQ.app

Reconciliation requires the exact operation ID and sequence returned by inspect:

  ELECTRON_RUN_AS_NODE=1 /absolute/verified/HQ.app/Contents/MacOS/HQ /absolute/verified/HQ.app/Contents/Resources/app/tools/updater/installer.cjs reconcile --target /absolute/installed/HQ.app --operation <operation-id> --sequence <sequence>

Inspection and recovery never authorize killing a live app or copying,
restoring or deleting profile data. Preserve both binaries on a held or
unknown result and resolve the exact reported condition before retrying.
