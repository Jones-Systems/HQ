## Decisions made, and why

- **Clean-room HQ Social service in `services/social`.** It is Python 3.11+, standard library only, loopback only, with SQLite storage and a sandboxed run worker. It speaks the same wire contract as Fieldnotes, so HQ's adapter and bridge stay unchanged, and Fieldnotes remains a compatible alternative endpoint.
  - **Why:** HQ had no runnable backend (B2-F1), and the deployed Fieldnotes is unreachable from HQ (B2-F2).
  - **Licensing:** Fieldnotes has no license, so only its interface informed the design. No source was copied.
- **The reference analyzers are HQ-authored, not ports of the native tools.** Each is deterministic and offline, and every result has a `basis` that says what it was computed from. Importing the native tools is owner decision D-B2-2.
- **The adapter contract is frozen for F3.** The `SocialWorkspacePort` methods, the `PortError` kinds, the feature names and the six bridge routes do not change. New capability arrives only as additive, feature-gated methods and routes, as set out in `spec.hq-social-backend#iface.adapter.001` and `#iface.extensions.001`.
- **Publishing is a default-off simulator only.** It writes to `outbox.jsonl`, and its receipts carry `simulated: true` (`#iface.publishing.001`). Real networks and credentials are owner decision D-B2-3.
- **#166 is accepted and carried as ancestor `992594a`** on the desktop and compat branches. That way B2 and #179 compose without conflict.
- **WS-S deviations accepted on review:**
  - 201 for a create and 200 for an update. HQ accepts any 2xx; Fieldnotes returns 200.
  - Strict keys on the brand and run bodies. The spec says "Accepts exactly".
  - 404 for a wrong GET or POST on a known path.
  - Fixed worker-failure texts.
  - No `project_id` or `hq-brand-project-v1` until WS-XS lands.
- **The duplicate-link wording stays as is.** The HQ service says `Each HQ reference can be linked once`; Fieldnotes says `Duplicate HQ reference target`.

**To fix before PR-2**, all on `work/hq-backend-social-service-20261103`:

1. **R1 (P2, bug).** A run input holding an out-of-range number such as `{"x": 1e400}` decodes to `inf`. `RunManager.submit` then calls `json.dumps(..., allow_nan=False)`, which raises `ValueError`. Only `RecursionError` is caught, so the response is a **500 instead of a 400**. HQ's own client cannot send this, because `JSON.stringify(Infinity)` gives `null`, but any other client can.
   - **Fix:** give `server.decode_object` a `parse_float` that rejects non-finite values, returning 400 `JSON object required`.
   - **Test:** add one in `tests/test_server.py` or `tests/test_runs.py`.
2. **R2 (P3, coverage).** No test covers a `wiki`-domain reference. The B5 lead asked for one. `references.DOMAIN_IDS` already includes `wiki`.
   - **Add:** a round trip through `POST /api/content` with a reference carrying `domain: 'wiki'`, `kind: 'page'`, a `sourceRevision` of `wiki-c1:…` and `returnDestination: {domain: 'wiki', destination: 'page/<ns>/…'}`.
3. **R3 (P3, test).** `tests/test_runs.py` `RealWorker` reaches only `failed`. Extend it so every tool's sample runs through the real worker to `succeeded`, with the output envelope `{ok: true, result}`.
4. **R4 (P3, flake).** Stabilize `test_concurrent_submissions_cannot_exceed_the_limit`.
   - **Fix:** set `request_queue_size` (for example 64) on `server.ThreadingHTTPServer`, and make the test report any status other than 201 or 409.
   - **Check:** run `test_runs` five times under admission.
5. **R5 (P3, docs).** `services/social/README.md` names `social_service/tools/README.md` in plain text. Make it a link.

**Optional hardening:** add `PYTHONSAFEPATH=1` to `runner.worker_environment`. The run directory holds no `.py` files, so this is defense in depth only.
