## Decisions and why

- **Evaluate the real Electron app, not the sealed browser preview.** The preview has no Design or Wiki, and it refuses dirty worktrees. The driver uses the acceptance runtime (Xvfb and bubblewrap). Its live mode runs the repository's real Planner behind a proxy that can be switched off, so offline and recovery behaviour is real.
- **Ownership,** agreed by thread message with F1, F6 and F4 and recorded in the assessment's "Lane routing" table:
  - F7 builds props-only components in `apps/desktop/src/navigation/` and `onboarding/`.
  - F1 owns `PresentationShell.tsx` and mounts those components. F1 also owns X3 (`services/observed-status.ts`), X6 rail compaction, X7 skip link and roving rail, X8 project semantics, X10 shell motion and X11.
  - F6 owns X4 for Wiki, X9 (Wiki reference provider), X14 in Settings and X16.
  - F3 owns X4 for Social. F2 and F3 own the X5 sample references.
- **F4 and the palette (X2).** In the long term the shell owns one palette, and Design registers its sections and commands with it. Until that registration API exists, Design keeps its own ⌘K and the shell palette yields to it (it doesn't open when the event's `defaultPrevented` is set).
- **B3 cancelled** so there wouldn't be two status stores. F1's builder builds the traffic-derived store, and F6 keeps consuming `useDataSources()` unchanged.
- **Window events contract:**
  - `hq-open-command-palette`
  - `hq-show-welcome`
  - the existing `hq-open-settings`, with `detail.source` of `social`, `work`, `wiki` or `appearance`
- **Status words** come from F6's Settings vocabulary: Ready, Stale, Indexing, Not set up, Unavailable, Checking…, Reachable, Unreachable, Sample data, Set up · not checked, Address rejected and Not qualified.
- **Reviews cover the seams between lanes only**: status truthfulness, shared vocabulary, references, offline behaviour and project identity. They are posted as PR review comments. All four backend PRs got "comment", because they were documentation and additive types with nothing to run in the app yet.

## Driver

[`f7/driver/drive.mjs`](f7/driver/drive.mjs) is a copy of the evaluation driver, kept for the record. It isn't product code. B4 is generalising it into `tools/dev-preview/` (#188).

- **Start a run:** `node drive.mjs <repo checkout> <label> <example|live|dead> [--no-wiki] [--profile <dir>]`. It uses the repository's `tests/acceptance/runtime.mjs` (Xvfb and bubblewrap) and starts Electron with a CDP port. The run root is `<repo>/.t3/f7-scratch`. Each run writes a sandbox-local fontconfig alias to Liberation Sans.
- **Control it** with [`f7/driver/c`](f7/driver/c), as `c <label> <route> '<json>'`:

  | Route | Use |
  | --- | --- |
  | `eval` | Run a JavaScript expression |
  | `shot` | Save a PNG under `/tmp/hq-f7-eval/evidence/<label>/` |
  | `key`, `type`, `click` | Drive the app |
  | `window` | Resize through `Emulation.setDeviceMetricsOverride` |
  | `media` | Emulate reduced motion and colour scheme |
  | `svc {"down":true\|false}` | Switch the live Planner proxy off and on |
  | `ledger` | Read the request ledger |
  | `errors` | Read console errors |
  | `restart` | Relaunch with the same profile |
  | `quit` | End the run |

- **Before running:** install the Electron binary once per checkout with `node node_modules/electron/install.js`.
