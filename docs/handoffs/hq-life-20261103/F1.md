## Decisions and why

- **The View Transitions API is called directly, with `flushSync`, instead of React's `<ViewTransition>` and `startTransition`.** React transitions keep the old UI on screen while Suspense content loads. Rail clicks looked dead, and `social-work.integration.test.tsx` failed (no `aria-current` right after a click). `navigateWithTransition` now:
  - runs the state update synchronously inside `document.startViewTransition({ update, types: ['hq-nav-<direction>'] })`;
  - falls back to the callback form;
  - updates directly when transitions are unsupported or motion is reduced.

  CSS uses `:active-view-transition-type()` so Back fades instead of rising.
- **Data sources moved from the rail into a top-bar popover.** The rail is a 64 px icon column now, and the six source controls were 13 tab stops before content (X7). The popover never probes on open, which keeps status truthful and cheap.
- **Element sizes and offsets are set through CSSOM** (`style.setProperty('--shell-pill-*')`, `--shell-rail-w`). The app's CSP is `style-src 'self'`, so inline `style` attributes are not allowed.
- **Popovers and menus set `data-hq-overlay="open"`.** Design's live preview is a native view drawn above the page. It hides only for dialogs or `[data-hq-overlay="open"]`, so without the attribute it covers menus.
- **SVG instead of text glyphs** (✓ ● ▲ ↻). They render as empty boxes on hosts without the glyph.
- **Project switching does not change reference semantics.** `reference-providers.ts` hard-codes `projectId: 'hq-local'` for Social and Work, so after a switch their references show as read-only ("another project"). That behaviour was already there. Changing it is a contract decision (see open questions).
