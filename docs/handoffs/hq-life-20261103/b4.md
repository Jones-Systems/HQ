## Decisions and why

- **Fix I1 in admission, not on the host.** The fix tolerates group-write only below a private Linux directory: one owned by the current uid with `mode & 0o077 === 0`.
  - Rejected alternatives: changing the umask or worktree modes, or adding a bypass flag. Each is host-specific, so lanes and the integration owner could not rely on it.
  - The rule keeps the security property: no other principal can traverse that directory. Other-write still refuses everywhere, and non-Linux platforms stay strict.
  - It ships as its own PR against foundation, so the T1 stack refs stay untouched, and must land before #182.
- **Dev-preview reuses the acceptance runtime.** The tool productizes lane F7's `/tmp` driver as `tools/dev-preview/`. It imports `tests/acceptance/runtime.mjs` and its fixtures read-only.
  - It adds no dependencies (CDP over Node's WebSocket) and changes no product code.
  - Its state lives under the git-ignored `<repo>/.t3/dev-preview/`.
  - It bypasses the acceptance evidence writer, which caps evidence at 16 runs with no eviction.
- **The local-checks mirror reads the workflow files on every run**, so it cannot drift from CI. It fails loudly on any step it cannot mirror; it does not run a partial set.
- **#94 is deferred to lane B1's HQR composite.** That avoids duplicate work; B1 was messaged twice. **#164 is held**, because its hosted bubblewrap install (`sudo apt` on the runner, issue #50 gate) needs owner approval.
- **Two load-sensitive assertions are recorded, not changed.** The repository rules forbid weakening tests, so each needs a diagnosis first.
- **#182's review findings are lane guidance plus proposed successor PRs.** The T1 lane owns those refs.
- **Process deviation:** builders opened their PRs before the independent review pass. The pass now runs before a PR is called ready, not before it is opened. Draft PRs were rejected because they defer CI.

- **I5 (P3):** Design has no one-command local run. The local-checks mirror addresses it.
- **#182 usage changes for lanes:**
  - Builds must run through `npm run`, because they require `npm_execpath`.
  - The closed argument grammar refuses `npm test -- <file>`, `--project` and `--maxWorkers`; use `node_modules/.bin/vitest run <filter>` for focused runs.
  - A SIGKILLed run leaves `.hq-storage.lock` in the worktree root. The refusal reads `Lock deadline; existing owner requires disposition: <path>`. Check that the PID recorded in the lock is gone, then delete the file.
  - CI's Foundation job calls Vitest directly, so `npm test` through the envelope is exercised only locally. Builder A's end-to-end run passed.
- **Load-sensitive assertions, not changed:**
  - The storage test "one total deadline covers all locks" asserts under 155 ms of wall time. It failed once at load average ~68 and passed on rerun.
  - The acceptance test "host fixture preserves ledger/digests" took 111 s at load average ~250 and passed.
- **Local gotcha:** a bare `node --test` in `tools/hq-cli` also runs the helper `test/e2e/cancel.mjs` and hangs. Use `'test/**/*.test.mjs'`.
- **Host capacity:** CPU peaked at 90.9%, and builders saw load averages of 68–250 while about 12 lanes ran. At the pause the host showed 65% CPU, load 15 and 23 GiB of RAM available. The disk is 97% used.
