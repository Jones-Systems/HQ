# HQ Wiki design (2026-11-03)

Authority effect: none. These are lane F6's design decisions for the Wiki module. The lane lead made them under the
owner's 2026-11-03 direction ("design decisions yourself"). Inputs:

- the [flow assessment](flow-assessment-20261103.md), findings WF-1 to WF-12;
- lane F7's cross-app findings X4, X9 and X14 (`docs/design/hq-cross-app-flow-assessment-20261103.md`, PR #185);
- the [HQ visual system](../../../docs/design/hq-visual-system/README.md), with the Design area as the visual bar;
- the shared [motion and feedback](../../../docs/design/hq-visual-system/motion-and-feedback.md) rules.

Reference products: Obsidian (reader, backlinks, hover previews), Notion (properties, calm empty states), Arc
(navigation that keeps context), Raycast (instant search), Linear (quiet chrome and keyboard flow).

## Goals

1. **Search as you type.** Results appear while typing, and Enter opens the best match.
2. **Reading comes first.** Title and text lead the page; provenance stays one click away.
3. **Links are previewable.** Hovering or focusing a link or backlink previews the target before you leave the page.
4. **Never a dead end.** Every problem shows in place with a way forward: Retry, Wiki settings, Search or Back. What
   already loaded stays visible.
5. **Navigation keeps context.** Back and Forward are instant for visited pages, and history and recent pages survive
   a switch to another domain and back.
6. **Alive but calm.** Short token-timed motion explains change, and reduced motion removes all movement.

## Layout

The Wiki fills the workspace (`presentation: 'fill'`). `.wiki-view` is a container (`container-type: inline-size`)
laid out as a grid with three parts:

```
┌ sidebar 232px ───────────┬ top bar 48px (sticky) ──────────────────────────────────────────────┐
│ Wiki                     │ ‹ ›  BusinessLessons › lessons › Pricing      [🔍 Search the Wiki  /] ⟲ │
│ ⌂ Home                   ├──────────────────────────────────────────────────┬───────────────────┤
│ REPOSITORIES             │  article column (max 72ch)                       │ right rail 248px  │
│ ● BusinessLessons   38   │                                                  │ On this page      │
│ ▲ App Development   33   │                                                  │ Linked from (4)   │
│ RECENT                   │                                                  │ Links on this page│
│   Pricing                │                                                  │                   │
│   Navigation             │                                                  │                   │
│ ─────────                │                                                  │                   │
│ ● Ready      ⚙ Settings  │                                                  │                   │
└──────────────────────────┴──────────────────────────────────────────────────┴───────────────────┘
```

- **Scrolling.** Only the content column scrolls (`.wiki-scroll`). The sidebar and top bar stay put.
  `.wiki-domain` stops scrolling itself.
- **Container widths.**
  - At 1100 px and wider: all three columns.
  - From 760 px up to 1100 px: the right rail's sections move below the article.
  - Below 760 px: the sidebar collapses behind a "Browse" icon button in the top bar and opens as an overlay
    (Escape or outside click closes it, and focus returns to the button).
- **Surfaces.** The sidebar uses `--hq-nav` with a hairline right border. The top bar uses `--hq-surface` with a
  hairline bottom border. Content uses `--hq-surface`. Cards and popovers use `--hq-surface-raised` (popovers add
  `--hq-shadow-overlay`).

## Sidebar (`nav aria-label="Wiki"`)

- **Title row.** "Wiki".
- **Home** item, with `aria-current="page"` on home.
- **Repositories group** (eyebrow `--hq-type-eyebrow`). One row per namespace: a status shape (`StatusChip` shape, no
  label), the display name and the page count (muted, tabular). Activating a row opens `topics/<ns>`, and the row
  shows the current state.
  - The row's title attribute and accessible name include the status word: "BusinessLessons, Ready, 38 pages".
- **Recent group.** Up to 8 pages from `session.recent()`, most recent first, each showing the page title.
  Activating one opens the page. The group is hidden when empty.
- **Footer.** A `StatusChip` with an overall word (Ready / Stale / Indexing / Not connected / Unavailable) and, when
  the host injected `openSettings`, a "Wiki settings" button with a gear icon.

## Top bar (`header`)

- **Back and Forward** are icon buttons with `aria-label` "Back" and "Forward" and titles "Back (Alt+←)" and
  "Forward (Alt+→)". They are disabled at either end.
- **Breadcrumb** (`nav aria-label="Breadcrumb"`): Wiki › repository › folders › page title, with the last crumb
  `aria-current="page"`.
  - Wiki opens home, and the repository crumb opens its topics. Folder crumbs are plain text.
  - On search the crumbs read "Search"; on topics they read "Topics › repository".
- **Search field.** An ARIA 1.2 combobox: `input[name=q]` with `role="combobox"`, `aria-expanded`, `aria-controls`
  and `aria-activedescendant`, a magnifier icon and a `/` key hint.
  - **Typing.** After 150 ms debounce (empty or invalid queries never request), a listbox popover under the field
    shows exact name matches first ("Go to …"), then the top 8 hits (title, repository badge, folder), and a final
    option, "Search all pages for “…”".
  - **Keys.** ↑ and ↓ move the active option; Enter opens it, or opens the full results page when no option is
    active. Escape closes the popover first, then clears the field. Ctrl/⌘+Enter always opens the full results page.
  - **Inline errors.** Empty or invalid input shows the existing validation text inline under the field (role
    alert) on submit.
  - **Repository filter.** It lives on the results page, not in the top bar.
- **History button** (clock icon, `aria-label="History"`, `aria-expanded`). It opens a popover listing session
  entries, newest first.
  - Each entry has a kind icon and a human label: the page title when known (`session.titleOf`), "Search “…”",
    "BusinessLessons topics", "Home" or "Disambiguation · label". The current entry carries `aria-current="step"`
    and a "Current" tag.
  - ↑, ↓ and Enter work in the list; Escape closes it and returns focus to the button.
- The old repeated "Topics · …" buttons, the ⌃/⌄ glyph toggle (X14) and the always-open filter fieldset are
  removed.

## Home (`aria-label="Home"`)

- **Header block.** Title "Wiki" plus one line: "Read and search BusinessLessons and App Development."
- **Repository cards** (two-up grid, `hq-lift`-style hover).
  - **Contents.** Display name, a `StatusChip` (Ready, Stale, Indexing, Unavailable), "38 pages", and "Updated 2
    days ago" from `commitTime` with the short commit in mono.
  - **Actions.** "Browse topics", and a "Details" disclosure that reveals the full provenance list (ref, commit,
    commit time, indexed, index freshness, remote freshness). The provenance hooks `data-field=…` and
    `data-freshness` stay inside that disclosure.
- **Recently opened.** The session's recent pages. Hidden when empty.
- **Topics to explore.** Up to 8 top-level topics per repository, largest first, as chips with counts (from
  `topicsResource`). Activating a chip opens that repository's topics.
- **Not connected (X4).** When every repository is unavailable with no source, or the host does not answer, Home
  shows one calm empty `Notice`, not two red panels.
  - **Copy.** Title "Connect the Local Wiki". Body: "Choose the BusinessLessons and App Development repositories in
    Settings to read and search them here."
  - **Actions.** "Open Wiki settings" (when injected) and "Try again". Cards, recent pages and topics are hidden.
- **Unrecognised destination.** An unrecognised destination keeps the inert notice (`data-notice="destination"`),
  restyled as an info `Notice`.
- **Loading.** Skeleton cards with `aria-busy` and a polite "Loading repositories…" status. Never a layout jump when
  data arrives.

## Search results (`search?q=`, `aria-label="Search results"`)

- **Page header.** "Results for “query”" plus the count line ("12 results", or "Showing 50 of 120 · narrow the search
  or the repositories").
- **Live query.** A large query field at the top of the page, synced with the top bar. Typing updates results live
  with a 200 ms debounce. The destination is committed with `ctx.openSearch(query, { replace: true })` after 600 ms
  idle, so typing never fills history.
- **Repository filter.** Chips "All", "BusinessLessons" and "App Development" (toggle buttons with `aria-pressed`;
  multi-select as today). With none selected, nothing is searched and "Choose at least one repository to search."
  shows (`data-state="no-repositories"`).
- **Exact name matches** come first as "Go to" cards. Ambiguous names list their candidates.
- **Hits.** Title (matched words wrapped in `mark`, built from text children only), repository badge, folder path
  (muted mono) and snippet with marked matches. The score is not shown; keep it as `data-score`.
  - ↓ from the field moves into the list (roving focus).
  - The first 8 hits rise in with a 28 ms stagger. Later updates do not re-stagger.
- **While refreshing,** the previous hits stay. A 2 px progress line runs at the top of the list (`aria-busy`).
- **Failures.** With hits shown: a `bar` notice "Couldn't update the results" with Retry. With nothing shown: an
  `ErrorNotice` with Retry and, for an outage, Wiki settings.
- **Empty.** "No pages match “query”", with "Search all repositories" when filtered and "Try fewer words" otherwise.

## Reader (`page/<ns>/<path>`, `aria-label="Reader"`)

- **Page header.** `h1.wiki-page-title` at 28/36, weight 650. A meta row below it: repository badge (opens topics),
  folder path (mono muted) and "Commit abc1234" (mono, full commit in `title`). Size and the full provenance go in a
  "Page details" disclosure (`data-field` rows kept).
- **Properties** (frontmatter fields). A compact two-column grid under the meta row, Notion-like, showing at most 6
  with "Show all N properties".
- **Content** (`.wiki-parsed`, max 72ch, 16/1.65).
  - Headings get stable ids (`wiki-h-<n>`) for the outline. Tables scroll horizontally inside a wrapper. Code
    blocks use mono on a sunken surface.
  - **Page links.** Accent buttons with a hover underline.
  - **Ambiguous links.** Dotted underline and a small count.
  - **Missing links.** Muted, with a dashed underline; never a button that navigates.
  - **External links.** Text with an external icon and the URL in the preview; never opened (no `href`, no
    `window.open`).
- **Link previews.** Hover for 350 ms, or keyboard focus for 500 ms, shows a preview card anchored to the link.
  - **Contents by link kind.** A page link shows title, repository and the first ~240 characters of text (from
    `pageResource`, prefetched on hover). An ambiguous link shows its candidates. A missing link says "No page named
    “X” yet". An external link shows the URL and "External links don't open from the Wiki."
  - **Behaviour.** One preview at a time. It stays while the pointer is over the card and closes on Escape, scroll or
    blur. It is `aria-hidden` supplementary content; activation is unchanged.
  - **Positioning.** CSS anchor positioning on a class-toggled anchor (`anchor-name` set by class, never by a style
    attribute), with a below-the-link fallback under `@supports not (anchor-name: --a)`.
- **Right rail.**
  - **On this page:** outline from the AST headings (h2/h3). Clicking scrolls smoothly (instantly under reduced
    motion), and the current section is highlighted.
  - **Linked from (N):** `.wiki-backlinks`, the backlink list with title and repository. Hovering or focusing an
    entry previews the context: the sentence or list item in the source page that links here, found in the source
    page's AST (fetched lazily, one at a time, cached).
  - **Links on this page (N):** `.wiki-outlinks`, grouped Pages / Ambiguous / Missing / External with counts, and
    collapsed beyond 8.
- **Raw pages.** An info `Notice` reading "Shown as plain text", with the reason in words, then the `pre` with
  wrapping. `data-raw-reason` is kept.
- **Loading.** Skeleton title, meta and paragraphs, with `aria-busy` and "Loading page…" kept as polite status text.
  Cached pages render at once.
- **Failures.**
  - **Not found:** "This page isn't in BusinessLessons", with "Search for “name”" and Back.
  - **Outage:** an `ErrorNotice` with Retry and Wiki settings.
  - **Backlinks failure:** a small `bar` notice in that section with Retry. The page still shows.
  - **Different page returned:** still rejected and shown as an error.
- **Disambiguation.** Activating an ambiguous link still opens the in-session disambiguation entry, restyled as a
  card list. Each candidate shows its title (lazily via `pageResource`), repository and path. ↑, ↓ and Enter work,
  and Back returns to the page.
- **Recent pages.** Opening a page records it with `session.visit(key, title)`.

## Topics (`topics/<ns>`, `aria-label="Topics"`)

- **Header.** "Topics" plus a repository segmented control (two toggle buttons, `aria-pressed`).
- **Filter.** A "Filter topics" field filters labels and page names live, keeping ancestors of matches visible and
  marking matches.
- **Tree.** Top-level topics are sections. Each has a chevron disclosure (`aria-expanded`), its label and a count
  badge. Children are nested with hairline indentation guides.
  - **Pages.** Rows showing `pageName(path)` plus the folder (muted), with "and N more" when the preview is truncated.
  - **Expanding** animates height (`grid-template-rows: 0fr → 1fr`, base duration) and rotates the chevron.
  - **Expand all / Collapse all** stay.
  - **Defaults.** Two levels open, and expansion state never leaks between repositories.
- **States.** Loading shows skeleton rows. Empty, error and mismatched namespace are notices as elsewhere.

## Feedback rules

- **Inline first.** Problems show where they happened. What loaded stays. `ErrorNotice` replaces `ErrorPanel` (same
  `role="alert"`, `data-state="error"`, `data-code` and `data-reason` hooks), and the raw code moves to a muted mono
  line.
- **Toasts (`ctx.toast`, optional).** Only for one-off events:
  - the first outage while showing cached content: a warning toast, "The Wiki isn't answering", with description
    "Showing pages you already opened." and a "Wiki settings" action. It uses id `wiki-outage` and is raised once
    per episode (`session.outage`).
  - recovery after that: a success toast, "The Wiki is back", on the same id.
  - a Retry that fails again: an error toast on the same id.
  Never toast what is already visible.
- **Settings route (`ctx.openSettings`, optional).** Offered in not-connected and outage states and in the sidebar
  footer. When it is absent, the action is omitted rather than shown as a control that cannot work.
- **Status words.** Ready, Stale, Indexing, Unavailable, Not connected. Raw enums are never primary text.

## Motion

Timing uses tokens only (`--hq-duration-*`, `--hq-ease-*`, `--hq-motion-*`). The UI static test enforces this.
Tokens reduce to zero under `prefers-reduced-motion` or `<html data-hq-motion="reduce">`.

| Change | Motion |
| --- | --- |
| View or page change | Content rises in (`wiki-rise`, `slow`, ease-enter); old content leaves at once; scroll position restores on Back/Forward (`session.saveScroll`) |
| Search popover, history popover, link preview | `wiki-pop` (`base`, ease-spring); exits are immediate |
| Result list update | First 8 items stagger in once per query; later changes swap without movement |
| Topic expand | Height via grid rows (`base`), chevron rotation |
| Hover and press | Colour (`fast`), press scale (`instant`) |
| Loading | Skeleton sheen; static under reduced motion |

Content is never left at partial opacity, and motion never delays focus or input.

## Keyboard

| Key | Action |
| --- | --- |
| `/` (outside a text field) | Focus the search field |
| ↑ / ↓, Enter, Escape | Search popover and history list |
| Ctrl/⌘+Enter | Full results page for the query |
| Alt+← / Alt+→ | Back / Forward (ignored while typing) |
| Escape | Close the topmost popover or preview, or the narrow-width sidebar overlay |

Shortcuts are listened for only while the Wiki is mounted. ⌘K stays the shell's (lane F7's cross-HQ palette).

## Accessibility

- **Landmarks.** Sidebar `nav "Wiki"`, top bar `header`, breadcrumb `nav "Breadcrumb"`, and `main` labelled by the
  view heading. Focus moves to the new view's heading after navigation, never on first mount.
- **Controls.** Icon-only controls have names. Status is never colour alone. Focus rings stay visible (`--hq-focus`).
  Hit targets are at least 28 px.
- **Patterns.** The combobox and listbox follow ARIA 1.2. Popovers return focus to their trigger. Previews are
  supplementary and never trap focus.

## Tests

The existing tests are behaviour specs. Where the UI changes by design, selectors and labels change in the same commit
while every behavioural assertion keeps its strength. That covers:

- the safety guarantees: inert rendering, no `href`, no egress, only the seven reads, logical requests;
- the sequence guard;
- the history semantics;
- the error-code headings.

The static tests evolved in the base commit:

- more `wiki-*.css` files, each scoped;
- `wiki-` keyframes;
- `@supports`, `@container` and `@starting-style` allowed;
- token-only motion timing.

They must not be weakened further.

## Not in scope here

- **Revision history and diffs.** The contract has no revision API. When lane B5 adds one, the reader gains a History
  tab with a commit list and word-level diff. Until then the Wiki does not show a placeholder.
- **The cross-HQ ⌘K palette** (lane F7). The Wiki contributes through the reference provider (W3).
- **Settings internals.** They follow `docs/design/settings/hq-settings-design-20261103.md`.
